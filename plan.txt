Build a functional prototype that simulates an enhanced machine translation workflow inside AutoCAD.

The prototype does NOT need to integrate with real AutoCAD or Autodesk MT API.

Instead:
- Build a simplified AutoCAD-like web UI.
- Create several sample DWG-like files using mock JSON data.
- Simulate Autodesk MT by calling the Gemini API for translation.
- The focus is the USER EXPERIENCE and workflow, not translation model research.

PROJECT OBJECTIVE

Prototype the following design challenge:

“How do we turn Autodesk’s existing machine translation capability into an intuitive, safe, transparent, and scalable translation workflow inside AutoCAD?”

The prototype should demonstrate:
1. Single-DWG translation from inside an opened drawing.
2. Batch translation from an AutoCAD-style Home page.
3. Pre-translation preview and filtering.
4. Safe output handling.
5. Same-file language management.
6. Translation progress.
7. Translation reporting.
8. Locate-in-drawing functionality.

Do not build an overly complex CAD engine. The drawing canvas can be a simplified 2D representation containing text boxes, leaders, annotations, dimensions, labels, and basic shapes.

6. TRANSLATION FILTERS
==================================================

Before translation, provide OPTIONAL filters.

Do not make object-type filtering the central feature.

A. OBJECT TYPES
Allow optional inclusion/exclusion:

☑ MText
☑ DBText
☑ MultiLeader
☑ Block Attributes
☐ Dimensions
☐ Table Cells

Purpose:
Users may want to translate general annotations while excluding structured content such as dimensions or title-block attributes.

B. LAYERS
Allow user to include/exclude layers.

Example:

☑ A-ANNO-NOTE
☑ M-ANNO-NOTE
☐ A-ANNO-DIMS
☐ S-GRID

C. PATTERN EXCLUSION

Provide simple predefined options:

☑ Skip numeric-only text
☑ Skip likely dimensions / levels
☑ Skip drawing references / short codes

Example strings that can be automatically excluded:
- D5.1
- W5.1
- FFL 0.000
- EL +12.500
- pure numbers

The purpose is NOT to claim better semantic translation.

The purpose is to avoid sending obvious non-linguistic strings to the translation API unnecessarily and to make the report cleaner.

Also allow:
[ + Add custom exclusion pattern ]

8. PROJECT GLOSSARY / PROTECTED TERMS
==================================================

Add an optional glossary section.

Two categories:

A. DO NOT TRANSLATE

Example:
HVAC
AHU
AHU-01
DN100
Cor-Ten

B. PREFERRED TRANSLATIONS

Example:
Finished Floor Level → <user-defined target term>
Fire Pump Room → <user-defined target term>

Allow user to add/remove entries.

This should be deterministic and user-controlled.

Do NOT build an AI system that infers project context.

When translating a sentence containing protected terms, preserve those terms.

For example:

Input:

AHU-01 is protected.

Gemini should translate the rest of the sentence while AHU-01 remains unchanged.

This can be implemented using placeholder masking before the API call and restoring the term afterward.

==================================================
13. GEMINI TRANSLATION
==================================================

Use Gemini API to simulate Autodesk MT.

Important:
In the prototype UI and documentation, describe Gemini as a SIMULATION of Autodesk MT API.

Do not present Gemini as the intended production translation engine.

Translation flow:

eligible text
→ apply protected-term masking
→ call Gemini
→ restore protected terms
→ store translated value

Use a concise translation prompt such as:

“You are simulating a professional machine translation API for an AEC/CAD application.

Translate the provided text from {sourceLanguage} to {targetLanguage}.

Rules:
- Return only the translated text.
- Preserve placeholders exactly.
- Preserve codes, measurements, and acronyms when present as placeholders.
- Do not explain the translation.”

Send strings individually or in a small structured batch.

Handle Gemini API failures gracefully.

23. UX PRINCIPLES TO DEMONSTRATE
==================================================

The prototype should clearly show how the workflow is:

INTUITIVE
- preserve existing Translate Selection / Translate All buttons
- use homepage for batch translation
- guide users through preview → output → translation → report
- avoid exposing technical API details

SAFE
- preview before translation
- allow separate translated copy
- allow same-file language versions without overwriting source
- protected terminology
- warnings for failed/locked/overflow objects

TRANSPARENT
- show included/excluded counts before translation
- show progress during translation
- detailed translation report afterward
- explain why objects were skipped or failed
- locate report entries directly in the drawing

SCALABLE
- batch translation from AutoCAD Home
- reusable filter presets
- reusable glossary
- multiple language versions
- status tracking across files
- filter report to only warnings/failures

==================================================
24. IMPORTANT SCOPE BOUNDARY
==================================================

Do NOT add:
- AI-based semantic drawing understanding
- AI deciding which layer means what
- AI automatically inferring discipline context
- another LLM before MT to decide whether something should translate
- complex CAD geometry
- real DWG parsing
- real Autodesk API integration

This project is primarily a UX/workflow prototype.

Gemini is only being used to simulate the translation output of Autodesk MT API.
